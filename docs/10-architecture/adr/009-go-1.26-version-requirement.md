# ADR-009: Go 1.26+ Requirement

**Date**: 2026-08-25
**Status**: Accepted
**Deciders**: Repository owner
**Supersedes**: [ADR-004](004-go-version-requirement.md)
**Related**: ADR-006 (No CGO Dependencies)

## Context

ADR-004 selected Go 1.24 as the consumer baseline before this repository had a
public tag or release. The rest of the gzh-cli family now develops and tests on
Go 1.26, and this repository is being prepared for public distribution. Keeping
a separate Go 1.24 compatibility lane adds policy and CI cost without protecting
an existing public release contract.

## Decision

The module requires Go 1.26.0 or newer. Development and CI pin the latest
approved Go 1.26 patch release, currently Go 1.26.7.

- `go.mod` declares `go 1.26.0` and `toolchain go1.26.7`.
- Regular CI runs with Go 1.26.7 and verifies the 1.26.0 minimum-version rule.
- The former Go 1.24.11 compatibility job is removed.
- Patch releases may advance without another ADR. Raising the minimum minor Go
  version requires an explicit compatibility decision and documentation update.

## Consequences

- Source builds and module consumers need Go 1.26 or newer.
- The repository can use Go 1.26 language and standard-library behavior without
  maintaining a down-level compatibility lane.
- This change is made before the repository's first public tag or release, so it
  does not break an established public version contract.
- Pure-Go and no-CGO constraints from ADR-006 remain unchanged.

## Verification

Release readiness requires all of the following:

- the declared toolchain is available from the official Go distribution;
- module download and verification leave `go.mod` and `go.sum` unchanged;
- build, test, vet, vulnerability, and repository validation gates pass with the
  pinned Go 1.26 patch release;
- public documentation consistently states Go 1.26+.
